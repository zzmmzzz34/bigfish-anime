## 0. 一句话现状

一台 Windows 电脑上的本地动漫 Web 站：**AniList 新番/评分/周表 + B 站热度 + MacCMS 播放层 + 跨源线路 + 线路健康检查/自动选线**。服务跑在 `http://127.0.0.1:8787`，可直接双击 `start.bat` 启动。

## 1. 怎么跑、怎么验

### 启动

```bat
双击 start.bat
```

脚本会找系统 Node，找不到就用 DSH 自带运行时：

```
C:\Users\ASUS\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe
```

### 开发模式

```bash
pnpm install
pnpm dev        # Vite 5173 + API 8787
```

本机没有全局 `node` / `pnpm`，验证时用：

```bash
export PATH="/path/to/node/bin:$PATH"
./node_modules/.bin/tsx server/index.ts
./node_modules/.bin/vite build --config web/vite.config.ts
./node_modules/.bin/tsc -p tsconfig.json --noEmit
```

### 数据与重置

- 所有运行时数据：`data/db.json`（源、历史、收藏、弹幕、评论）。
- 想看干净首页：停服务 → 删除 `data/db.json` → 重启。
- 源列表默认值在 `server/lib/store.ts`，删掉 db 后会重新种入。
- 端口被占：`netstat -ano | grep 8787` → `taskkill //PID <pid> //F`。

### 自测脚本（Playwright 复用系统 Edge）

```bash
node scripts/shot.mjs <url> <out.png> [w] [h] [waitMs]
node scripts/e2e.mjs               # 播放 + 弹幕 + 评论
node scripts/mock-bangumi.mjs      # 本地 Bangumi mock（可选）
```

## 3. 架构（当前）

```
浏览器
 ├─ React 19 + Vite（web/src）
 │   ├─ pages: Home / Airing / Ranking / Catalog / Detail / Player / Search / Library / Sources
 │   ├─ components: Sidebar / Hero / PosterCard / Stage / DanmakuLayer / Comments
 │   └─ lib: api / hooks / lineHealth / types
 │
 └─ /api（Express 5，server/）
     ├─ discover / airing / ranking   ← AniList + B 站（anilist.ts / bilibili.ts）
     ├─ catalog/:id + matches         ← catalog.ts（B站 or anilist-<id>，严格匹配 + 跨源线路）
     ├─ search / detail / alternates  ← sources.ts（MacCMS/Kazumi）
     ├─ lines/health + report         ← health.ts（线路体检 + 成功率）
     ├─ proxy / image / resolve       ← proxy.ts（CORS/Referer/嗅探）
     ├─ danmaku / comments / history / favorites
     └─ sources                       ← 片源 CRUD
```

### 关键数据流

1. `GET /api/discover`：并行拉 B 站追番/评分/播放榜 + 在播 + MacCMS 最新；Hero 用追番榜（按系列去重、排除剧场版）。
2. `GET /api/catalog/:id/matches`：B 站标题 → 所有源搜索 → **严格同名**（季数、配音版本、排除解说）→ 逐个详情 → 线路。
3. `POST /api/lines/health`：每条线路首集 → m3u8 列表/子列表/首分片 → 状态 + 延迟 + 历史成功率；`force=1` 跳过缓存。
4. 前端 `useLineHealth` + `recommendedIndex` + `useAutoLine`：绿/黄/红/灰 → 推荐 → 自动切 → 记忆/恢复用户选择。
5. 播放：`/play/:sourceId/:vodId/:line/:ep` → `/api/detail` → `/api/proxy`；播到 5s / fatal 时 `POST /api/lines/report`。
6. 统计：`data/db.json` 的 `lineStats[sourceId|host] = { ok, fail, lastAt }`，下次选线参与加权。
7. AniList：`getSeasonAnime` / `getTopAnime` / `getWeekSchedule` → `zhTitle()` 用 `data/seed/anilist-zh.json` 映射中文 → 首页/新番/周表/排行；点击进入 `/catalog/anilist-<id>`，再用中文标题匹配片源线路。

## 4. 关键决策与原因（不要轻易推翻）

| 决策 | 原因 |
| --- | --- |
| AniList 做新番/评分/周表 | B 站番剧库不全、放送表稀疏；AniList 当季/周表完整，评分方差更合理。Bangumi 被 DNS 污染 + SNI 阻断。 |
| B 站只做热度/中文 | 追番、播放、中文标题是 B 站强项；Hero 和「大家都在追」继续用 B 站。 |
| 中文标题用 bangumi-data 离线种子 | Bangumi API 不可达，但 `bangumi-data` 提供 AniList ID/日文标题 → 中文译名；当季 30 部命中 27 部。 |
| AniList 详情保留英文简介 | 暂无可稳定获取的中文简介源；页面明确标「英文简介 · AniList」，不伪装成中文。 |
| 首页不做「周一~周日」周表 | B 站放送表每天只有 1–2 部有效番剧且多少儿/国创，7 个 tab 会很空；用「本季新番」网格替代。 |
| 不把 360 资源设为默认 | API 可用，但 CDN `vod2.maowushi.com` 全 502；宁缺毋滥。 |
| 跨源匹配用严格同名 | 否则「芙莉莲第二季」「国语版」会混进第一季线路。 |
| 健康检查异步做 | 不阻塞详情渲染；4 条线路约 2–4 秒出结果，缓存 10 分钟。 |
| 健康检查只测首集首分片 | 成本可控；后续集数仍可能失效，这是已知限制。 |
| 弹幕/评论本地 JSON | 单机自用；不引入账号与数据库。 |
| 默认只监听 127.0.0.1 | 个人自用，避免暴露到局域网。 |

### Bangumi 接入备忘（v0.7：API + SQLite）

- `server/lib/bangumi.ts`：`bgmByAniList` / `bgmByTitle` → `GET /v0/subjects/{id}`；**SQLite 新鲜缓存 → 反代 → 旧缓存（stale）**。
- `server/lib/bangumiDb.ts`：`data/bangumi.db`，WAL；表 `bgm_subject` / `bgm_episode` / `bgm_sync`；7 天新鲜期。
- `server/lib/bangumiPrefetch.ts`：当季/收藏预热，350ms 间隔；`GET /api/bangumi/prefetch/status`。
- 配置：`config.env` → `BANGUMI_BASE=https://bgm.example.com`；状态：`GET /api/bangumi/status`；缓存统计：`GET /api/bangumi/cache/stats`。
- 原 `workers.dev` 被 DNS 污染 + SNI 阻断；绑定自定义域名 `bgm.example.com` 后正常。
- 关键坑：Worker 的 `POST /v0/search/subjects` 对中文关键词返回空（CLANNAD 正常），所以**不要依赖搜索**，用 seed 里的 Bangumi ID 直查。
- 真实数据：芙莉莲 `8.5 / #43 / 36,701 人评分 / 中文简介`，AniList 9.1；药屋第三季 `7.4 / #1336`。
- 未映射条目（如赛博朋克 S2）自动回退 AniList 英文简介。

### B站弹幕备忘（v0.8）

- `server/lib/bilibiliDanmaku.ts`：`season_id` → `pgc/view/web/season` 取每集 `cid` → `x/v1/dm/list.so?oid=cid` XML → 解析 `<d p="time,mode,fontsize,color,...">`。
- 缓存：内存 10min + `data/cache/bilibili-dm/<cid>.json` 6h；XML 最多 3000 条。
- 入口：B站详情页「开始观看」带 `?catalog=<season_id>`；播放器 `/api/danmaku/bilibili?season=&ep=`，切集/切线路会保留 query。
- 当前只覆盖 B站番剧详情；AniList/片源详情没有 season 映射。按集数下标对齐，PV/特别篇可能错位。
- 参考：AniCh 后端给 `bili_cid`，客户端按 `type=1&oid=cid&segment_index` 拉 protobuf；Kazumi 走 DanDanPlay 签名 API（AppId/Key 构建注入），按 BGM ID/标题匹配。

## 6. 已知问题 / 技术债

1. **健康检查只验首集**：后续集数可能单独失效；可点刷新强制重检，但不会逐集检测。
2. **成功率是 host 级**：同一源同一 CDN 域名的多条线路共享统计；不同清晰度/线路的差异会被平均。
3. **成功阈值 5 秒**：播到 5 秒才记成功；如果前 5 秒正常、后面挂掉，会同时产生一次成功和一次失败。
4. **unknown 不计数**：分享页/播放页标灰，不计入「N 条可用」；用户可能误以为坏掉。
5. **自动选线会切换列表**：健康结果回来时若用户正在看第 1 条，会跳到推荐线路（集数通常一样）。可加「已切换至最快线路」提示。
6. **线路重复**：同源 2 条线路（主/备）都展示，4 条里有 2 条可能是同一 CDN 的备份。
7. **catalog 匹配覆盖不全**：片源命名差异大时匹配不到；`strictMatch` 已排除季数/配音串味。
8. **缓存只覆盖预热/访问过的条目**：没缓存 + 反代失效时回退 AniList；`data/bangumi.db` 要定期备份。
9. **Bangumi 中文搜索不可用 + 无评论 API**：搜索接口对中文返回空，只能靠 seed 的 Bangumi ID 直查；评论/讨论没有 v0 接口，Phase 2 才考虑 HTML 抓取。
10. **中文标题覆盖约 90%**：`bangumi-data` 没收录的新番会退回日文标题，片源匹配可能失败。
11. **种子需要手动同步**：`scripts/sync-bangumi.mjs` 依赖 GitHub API；数据不会自动更新，建议每月跑一次。
12. **AniList 限流/依赖**：GraphQL 匿名调用有速率限制，周表要 3 页；失败时首页会退回 B 站数据。
13. **B 站讨论度/热梗未接**：目前只用追番/播放榜，评论/热梗在路线图。
14. **B站弹幕范围有限**：只覆盖 B站番剧详情，按集数下标对齐；XML 上限 3000 条；AniList/DanDanPlay 源还没有。弹幕没有 WebSocket/屏蔽词/举报。
15. **没有自动化测试框架**：只有 Playwright 脚本，不是 CI。
16. **包体偏大**：hls.js + 图标 960KB；可按路由拆包。
17. **JSON 存储**：并发写靠 200ms 防抖 + 原子 rename；没有事务/迁移。
18. **`removedSources`**：删除内置源后写入 db 顶层字段，getDb 里靠 `as any` 读取；重构时注意。
19. **播放器“换线路”是整页跳转**：`<a href>`，不是 SPA 内切换。
20. **健康检查/统计没有鉴权/限流**：本地自用可接受，暴露公网要加。

## 8. AniCh 研究笔记（2026-10-20）

仓库：<https://github.com/Sle2p/AniCh> · **Dart / Flutter** · 6.9k stars · **无 LICENSE**

### 它是什么

- 多平台在线动漫 App（Android/iOS/Windows），支持超分辨率、弹幕、离线缓存、追番、分集评论。
- **不是客户端规则抓站**：它有自己的后端 `https://ani.emmmm.eu.org`，客户端只调 API 拿 protobuf。
- 关键文件：
  - `api.json`：`baseUrl`、`bilibiliApiUrl`、`qqVideoApiUrl`、`apis[]` 多域名回退、`githubProxyUrl`
  - `lib/src/apis/bangumi.dart`：`GET /vod/{id}/{episode}`、`GET/POST /danmaku`
  - `lib/protobuf/bangumi.pb.dart`：`vod_item_ { url, sort, type, caption }`
  - `lib/src/pages/bangumi_vod/controller.dart`：`getPlayUrl()`、`urlDecode()`（base64 去混淆）、`setPlayer()`
  - `lib/src/widgets/ns_danmaku/*`：弹幕渲染、屏蔽、设置
  - `pubspec.yaml`：`media_kit`、`dio`、`protobuf`、`get_storage`

### 值得学

1. **每集多线路 + caption/type**：后端返回的是「这一集」的 `vod_item_` 列表，而不是「整部番的线路」。我们目前是 line→episodes，遇到「第 3 集只有 A 源、第 4 集只有 B 源」会不灵活；可给 `Episode` 加 variants。
2. **多域名回退**：`api.json` 的 `apis[]` 是显式的备用入口。我们的 `Source` 可以加 `apiMirrors[]`，健康检查时一起试。
3. **弹幕源聚合**：B 站 + QQ 视频弹幕，按 episode/segment 拉取，protobuf 解码，支持屏蔽/举报。我们下一步可先做 B 站弹幕导入。
4. **统一播放接口**：客户端只认 `/vod/:id/:ep` 的标准化结构；我们已有 `/api/detail`，可以再加一个 `/api/vod/:source/:id/:ep` 给未来的插件/客户端复用。
5. **播放器能力**：`media_kit`（libmpv）支持格式比 Web 的 hls.js 多；Web 端若要 FLV 可加 `mpegts.js`，但不要为此重写播放器。
6. **产品功能清单**：超分辨率、离线缓存、追番管理、分集评论、弹幕举报——可作为路线图参考。

### 不要照搬

- **没有 LICENSE**：不能复制代码/资源，只能学思路。
- **强依赖中心后端**：我们的卖点是本地配置、规则透明、源可插拔；不要改成必须依赖某个公共服务。
- **URL base64 混淆**：对本地自用没意义，反而增加调试成本。
- **它没有线路健康检查**：`currentLineIndex = 0` 直接播第一条；我们在这一点上已经更靠前，不要退回去。

### 结论

AniCh 验证了「后端归一化 + 多源 + 弹幕聚合」的产品方向；我们保留本地优先的架构，吸收 **per-episode variants、镜像回退、B 站弹幕导入** 三点即可。
